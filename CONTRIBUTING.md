# Разработка и передача пакета

## Что редактировать

```text
figma-local-mcp/
  .codex-plugin/plugin.json    Метаданные пакета Codex
  .mcp.json                    MCP для установки как плагина
  src/                         MCP-инструменты, схемы и bridge
  plugin/                      Figma plugin: TypeScript + HTML + manifest
  skills/figma-local-design/   Инструкции, профили, примеры правил
  runtime/                     Собранный Node-сервер и лицензии зависимостей
  scripts/setup.mjs            Переносимая установка и генерация конфигурации
  scripts/package.py           Сборка ZIP из разрешённого списка файлов
  test/                        Проверки сервера, плагина и переносимости
```

Не правьте `runtime/server.mjs` или `plugin/code.js` вручную: они пересобираются. В проекте нет внешней службы, базы данных или обязательного API-ключа.

## GitHub и SkillStore

GitHub-репозиторий — источник кода: он может содержать workflow-файлы, документацию для контрибьюторов и тесты. SkillStore получает отдельный пакет, собранный по белому списку:

```bash
npm run pack:skillstore
```

Загружайте в SkillStore только `dist/skillstore/figma-local-design`, а не корень репозитория. Сборщик исключает и отклоняет `.github`, `.git`, `.skillstore-meta.json`, `installation.json` и символические ссылки. Локальные `generated/`, `.mcp.json` и `.skill-install.json` также игнорируются Git.

## Как пересобрать

Для разработчика нужны Node.js 22+, npm и Python 3. Из корня проекта:

```bash
npm ci
npm run release
```

`release` запускает TypeScript-проверку, собирает Figma-плагин и Node-сервер с зависимостями, проверяет тесты, затем создаёт:

```text
dist/figma-local-mcp-0.6.2.zip
dist/figma-local-mcp-0.6.2.zip.sha256
```

Получателю передавайте ZIP и при желании файл контрольной суммы. Архив уже включает `INSTALL.md`, `CUSTOMIZE.md` и исходники для дальнейших изменений. Ему не нужны `npm ci` и Python.

В ZIP не попадают `node_modules`, `generated`, `dist`, локальные регистрации клиента, коды подключения или домашние настройки. Упаковка использует явный список входных файлов и отклоняет симлинки. В `runtime/THIRD_PARTY_NOTICES.md` сохраняются лицензии зависимостей, которые действительно вошли в bundle. Не добавляйте пользовательские конфиги/токены в исходники или документы.

## Версии и проверки

Для нового релиза обновите версии в package.json, package-lock.json, src/server.mjs и .codex-plugin/plugin.json согласованно. Название архива берётся из package.json. Если меняются только внутренние правила команды, всё равно передайте новый архив и обновите установленные копии скилла.

Минимальные проверки перед передачей:

- `npm test`: поведение операций, ошибки, setup и запуск bundle из отдельной папки без node_modules.
- Запуск `scripts/package.py`, проверка состава ZIP и SHA256.
- Для изменений в Figma API/рендеринге: дополнительно открыть development plugin в настоящем Figma и проверить макет. Автотесты этого не заменяют.

При наличии системных навыков Codex можно дополнительно запустить `quick_validate.py` из skill-creator для папки скилла и `validate_plugin.py` из plugin-creator для корня пакета. Эти валидаторы не нужны получателю.

## Два способа распространения

**ZIP + setup** — основной проверяемый путь, не требует marketplace. Установка описана в [INSTALL.md](INSTALL.md).

**Плагин в каталоге Codex** — комплект уже содержит `.codex-plugin/plugin.json`, скилл и `.mcp.json`. Можно включить его в поддерживаемый вашей командой каталог и проверить установку на целевой версии Codex. Конфигурация плагина использует `node ./runtime/server.mjs` с `cwd: "."`; разрешение пути относительно установленного корня зависит от поддержки локальных плагинов в клиенте. Если этот режим недоступен, standalone setup генерирует однозначные абсолютные пути. Установка в каталог и публикация в общий реестр не выполнялись.

Детали упаковки Codex: [официальная документация](https://developers.openai.com/plugins/build/plugins). Marketplace и публичная публикация — отдельные операции; наличие manifest не означает, что пакет опубликован или установлен другим пользователям.

## Доработка возможностей

Добавляйте схему команды в `src/`, реализацию в `plugin/`, соответствующие MCP-аннотации и тесты. Сохраняйте работу через локальный Plugin API. Операции, которых нет в нём или которые требуют отдельного доступа, нельзя получить одной инструкцией в SKILL.md.

При передаче результатов проверок отделяйте фактически протестированное от предположений: в текущем окружении протестированы локальная сборка/протокол и имитация Plugin API; настоящий Figma Desktop и установка plugin bundle через UI требуют отдельной проверки.

Сборка также создаёт assets/runtime-payload.json.gz и runtime-release.json внутри скилла. В payload намеренно нет skills/ (чтобы избежать рекурсивных архивов) и generated/ (локальные ключи). Bootstrap копирует текущие инструкции отдельно при развёртывании. scripts/package.py создаёт отдельный dist/figma-local-design-skill-0.6.2.zip из того же белого списка. Для HTTPS-распространения разместите runtime-payload.json.gz и передайте SHA256 из runtime-release.json; пользовательский адрес не подставляется автоматически.
