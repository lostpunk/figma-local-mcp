# Установка Figma Local Design

Это комплект из локального MCP-сервера, development plugin для Figma и скилла для AI-агента. Сервер уже собран с зависимостями; устанавливать npm-пакеты получателю не нужно.

## Что потребуется

- Node.js версии 22 или новее. Проверка: `node --version`.
- Figma Desktop и файл с возможностью редактирования и запуска development plugins.
- Codex или другой клиент, поддерживающий локальные MCP-серверы через stdio.

Figma API token не нужен. Сервер не обращается к REST API и официальному MCP Figma. Лимиты AI-клиента и обычные ограничения Figma сохраняются.

## Быстрый путь для Codex

1. Распакуйте архив и поместите папку `figma-local-mcp` в постоянное место. Не запускайте установку прямо из архива.
2. Откройте терминал в этой папке и выполните:

```bash
node scripts/setup.mjs --codex
```

Команда регистрирует MCP в Codex и устанавливает скилл `figma-local-design`. Для неё нужен доступный в терминале Codex CLI. Она не меняет сторонние MCP-настройки, правила проектов или конфигурацию Figma. Если скилл уже существует, команда остановится; для обновления с резервной копией добавьте `--update-skill`.

3. Перезапустите Codex и откройте новую задачу, чтобы загрузились инструменты и скилл.
4. В Figma Desktop откройте файл → **Plugins → Development → Import plugin from manifest…**. Выберите `generated/figma-plugin/manifest.json` из распакованной папки: этот manifest создаёт установщик.
5. Запустите **Figma Local MCP Auto**. Старый ручной плагин называется **Figma Local MCP** и показывает поле кода. Если Figma требует выданный ID, создайте development plugin через **New Plugin** и замените только `id` в нашем manifest на выданный ID.
6. Плагин автоматически подключится к MCP. Вводить код не нужно. Держите окно открытым.
7. Попросите прочитать текущий файл, затем создать нужный style guide или макет. Например:

> Используй $figma-local-design. В открытом пустом файле создай style guide и экран входа с использованием профиля shadcn/ui. Привяжи цвета и текст к токенам и стилям, покажи PNG.

## Если Codex CLI нет или используется другой клиент

В распакованной папке выполните:

```bash
node scripts/setup.mjs
```

Откройте `generated/mcp.json`: там находятся точные `command` и `args` для **вашего** компьютера. Добавьте `figma_local` как stdio-сервер в настройках клиента. Для Codex также подготовлен `generated/codex.toml`: добавьте его секцию в конфигурацию, сохранив существующие настройки. Не вставляйте секцию повторно, если `figma_local` уже есть.

Скилл в Codex можно установить отдельно:

```bash
node scripts/setup.mjs --install-skill
```

Для другого агента перенесите целиком папку `skills/figma-local-design` в его каталог скиллов. MCP и скилл подключаются отдельно: копирование SKILL.md не запускает сервер. Клиенты без поддержки скиллов могут использовать MCP напрямую, но правила нужно передать их собственным механизмом инструкций.

Файлы `.codex-plugin/plugin.json` и `.mcp.json` дополнительно позволяют включить комплект в поддерживаемый каталог плагинов Codex. В этой версии проверен standalone-путь выше; установка из каталога в интерфейсе Codex ещё не проверена. Не подключайте одновременно оба варианта: два сервера займут один порт.

## Обновление и неполадки

- **Manifest error: Invalid value for devAllowedDomains с адресом 127.0.0.1.** В версии 0.3.1 manifest и UI используют `ws://localhost:3055`. Импортируйте обновлённый `plugin/manifest.json`; одного изменения manifest недостаточно, адрес в `plugin/ui.html` должен совпадать. Сервер по-прежнему слушает только loopback-интерфейс. Формат localhost предусмотрен [документацией manifest](https://developers.figma.com/docs/plugins/manifest/).
- **Папка перемещена.** Пути в регистрации абсолютные. Повторно сгенерируйте конфигурацию и обновите регистрацию. Не удаляйте исходную папку после установки: MCP запускается из неё.
- **Сервер уже зарегистрирован по другому пути.** Установщик сохранит его настройки. Посмотрите `codex mcp get figma_local`; если это старая установка именно этого MCP, удалите её через `codex mcp remove figma_local`, затем повторите setup.
- **Занят порт 3055.** Закройте другой экземпляр MCP/клиента. Не запускайте `npm start` отдельно: MCP-клиент сам создаёт процесс.
- **Плагин отключён.** У персонального плагина связь восстанавливается автоматически с интервалом до 10 секунд. После кнопки «Отключить» нажмите «Подключить» или запустите плагин заново. При неверном ключе повторите setup и переимпортируйте его manifest. Если открыт старый ручной плагин с полем кода, повторите setup и импортируйте `generated/figma-plugin/manifest.json`. Ключ через чат не передаётся.
- **Изменение зависло/соединение оборвалось.** Проверьте файл перед повтором: отправленная операция могла выполниться.
- **Другой файл Figma.** Запустите плагин в этом файле и подключите его. Один процесс обслуживает один открытый файл.
- **Обновились правила скилла.** `node scripts/setup.mjs --install-skill --update-skill`. Предыдущая копия сохраняется в `generated/`. Начните новую задачу в Codex. Проектные правила из `.figma-design.json` обновление не затрагивает.
- **Ограничения организации.** Если development plugins запрещены, потребуется доступный в организации способ их использования; MCP не обходит эти ограничения.

Node.js должен быть доступен в терминале. Если интерфейс клиента не видит `node`, используйте абсолютный путь из `generated/mcp.json`. Установщик протестирован на macOS, в том числе в каталоге с пробелами; реальная установка на Windows/Linux не проверена. Создание макета и экспорт проверены в Figma Desktop; автоматические тесты дополнительно имитируют Plugin API и проверяют автоподключение.

Прочитанные макеты передаются в контекст MCP-клиента и могут отправляться его AI-провайдеру. Локальный сервер не означает локальную модель.

Настройка UI-библиотеки и правил: [CUSTOMIZE.md](CUSTOMIZE.md). Как пересобрать архив: [CONTRIBUTING.md](CONTRIBUTING.md).

- **Подключено, но команды завершаются по таймауту.** В 0.3.2 исправлена передача ответов из Figma Desktop при пустом `event.source`. Закройте и снова запустите плагин из обновлённой папки, затем подключитесь заново.
- **Empty range selected при создании текста.** В 0.3.2 исправлена загрузка шрифтов для новых пустых текстовых слоёв. После обновления перезапустите плагин.

## Переход на автоматическое подключение

Запустите `node scripts/setup.mjs`, перезапустите MCP-клиент и замените старый импорт development plugin на `generated/figma-plugin/manifest.json`. Исходный `plugin/manifest.json` остаётся ручным вариантом. Не переносите один manifest отдельно от его code.js и ui.html.

Установщик сохраняет ключ между запусками и обновлениями. Для смены ключа закройте сервер и плагин, удалите только `generated/pairing-key.json`, снова запустите setup и перезапустите клиент/плагин. Автоматическое восстановление не повторяет команды: после обрыва во время редактирования агент сначала проверяет файл.

Передавайте другим людям только ZIP из `dist/`: папка `generated/` содержит ваш локальный ключ. У каждого получателя setup создаст новый.

## Проверка тарифа и лимита страниц

В версии 0.5.0 плагин показывает количество страниц и поле «Тариф команды этого файла». Тариф автоматически недоступен через публичный API; до подтверждения применяется предел безопасности в три страницы. Настройка сохраняется в текущем документе. После переноса файла в другую команду или смены тарифа обновите выбор. Агент читает эти сведения через get_document после подключения.

Для обновления перезапустите Figma Local MCP Auto. Импортировать manifest заново не нужно. MCP-клиент при следующем запуске загрузит новые описания инструментов и необязательный аргумент pageId для style guide.

## Если вы получили только скилл

Распакуйте `figma-local-design-skill-0.7.8.zip` в каталог навыков вашего агента, сохранив папку `figma-local-design` целиком. Попросите: «Используй $figma-local-design и установи всё необходимое для Figma». Агент выполнит scripts/install.mjs из скилла; исходная папка MCP не требуется. Данные установки сохраняются в локальном каталоге Codex.

После подготовки импортируйте выбранный manifest в Figma через **Plugins**, затем запустите **Figma Local MCP Auto**. При необходимости перезапустите MCP-клиент для загрузки инструментов. Уже установленные MCP и правила скилла сохраняются.

## Каталоги для импорта изображений и SVG

По умолчанию сервер не читает файлы по произвольным путям. Выберите каталог ресурсов проекта: `node scripts/asset-access.mjs --allow /absolute/project/assets` из установленного runtime. `--list` показывает каталоги, `--remove PATH` отзывает доступ, `--clear` очищает список. Перезапуск MCP не требуется. Локальная настройка сохраняется при обновлении и не включается в архив.


## Обновление ранее установленного скилла — 0.7.17+

После обновления папки скилла выполните из этой папки:

```bash
node scripts/install.mjs --update --no-open --non-interactive
node scripts/install.mjs --check
```

Первая команда синхронизирует отдельную установку MCP и персональный Figma-плагин. Она проверяет подготовленную сборку до замены и установленные файлы после неё, сохраняет резервную копию и откатывает заменённые файлы при ошибке. Ключ, разрешённые папки импорта, логи, правила проекта и ID плагина сохраняются. Не переносите manifest: при прежнем пути достаточно перезапустить существующий Figma Local MCP Auto. Если старый плагин был импортирован из другой папки, один раз импортируйте путь, который указал установщик.

`--check` сверяет файлы и версии на диске, не меняя макет. Если файлы изменились даже без смены номера версии, `--update` восстановит их из установленного скилла. Нужен Node.js 22+; npm-зависимости и отдельный checkout для этого не требуются. Без доступного Codex CLI добавьте `--no-register`, сохранив существующую регистрацию MCP.

Запущенные процессы продолжают использовать прежний код. Полностью перезапустите MCP-клиент и Figma Local MCP Auto, затем попросите агента проверить get_connection: версии server/plugin/skill должны совпасть, readiness.ready — быть true. Только после этого обновление проверено в открытом файле Figma.
