# Правила дизайна и UI-библиотеки

Скилл управляет решениями агента, MCP выполняет команды. Правило в Markdown не добавляет новый API и не является техническим запретом для клиента, который не использует скилл.

## Правила конкретного проекта

Скопируйте `skills/figma-local-design/assets/design.config.example.json` в корень вашего проекта под именем `.figma-design.json`. Например:

```json
{
  "profile": "shadcn-ui",
  "library": {
    "name": "shadcn/ui",
    "mode": "reference",
    "docs": "https://ui.shadcn.com/docs",
    "components": {}
  },
  "foundation": { "name": "Acme", "theme": "light", "fontFamily": "Inter", "spacing": [4, 8, 16, 24, 32, 48] },
  "viewports": { "desktop": 1440, "mobile": 390 },
  "rulesFiles": ["design/rules.md"],
  "rules": ["Основное действие должно быть различимо", "Для повторяющихся элементов использовать компоненты"]
}
```

Создайте `design/rules.md`, например:

```markdown
# Правила Acme

- Использовать существующие цвета бренда, не создавать новую палитру при правке экрана.
- В формах всегда показывать подписи полей; placeholder не заменяет подпись.
- Тексты интерфейса — на русском, без выдуманных бизнес-метрик.
- Для экранов заказа предусмотреть пустое состояние и ошибку оплаты.
- Основные кнопки на мобильном экране делать высотой 48 px.
```

Агент читает конфигурацию и перечисленные файлы. Приоритет: явный запрос пользователя → правила проекта → профиль → общие правила скилла. Это соглашение для агента, а не конфигурационный файл Node-сервера; без вызова/выбора скилла MCP сам его не читает.

## Профиль shadcn/ui

По умолчанию выбран shadcn/ui: он удобен для связи макета с будущими React-компонентами и семантическими токенами. Правила находятся в `skills/figma-local-design/references/shadcn-ui.md`, стартовая палитра — в `assets/shadcn-starter.json` внутри того же скилла.

Пакет не устанавливает React, Tailwind или shadcn в ваш продукт и не содержит сторонний Figma-кит. В режиме `reference` агент создаёт собственные нативные Figma-компоненты по принятой системе и документации. Он должен обозначать их как аналоги, если соответствие конкретной версии не проверено. У shadcn нет единого обязательного внешнего вида для всех проектов: учитываются ваши компоненты и тема. См. [документацию темы](https://ui.shadcn.com/docs/theming).

## Настоящие компоненты Figma-библиотеки

Если нужны именно экземпляры вашего кита:

1. Поместите необходимые основные компоненты в подключённый файл доступным вам способом.
2. Через MCP найдите их и проверьте ID и тип COMPONENT.
3. Укажите `library.mode: "local-components"` и соответствия в `library.components`, например роль `Button/Primary` → фактический ID компонента в этом файле.

При отсутствии компонента скилл попросит его предоставить или согласовать переход в `reference`. Он не будет выдавать нарисованный аналог за настоящий экземпляр. Автоматический импорт удалённых библиотек этот MCP пока не поддерживает.

## Material UI или своя библиотека

Укажите `profile: "custom"`, `profileFile: "design/ui-library.md"` и имя/официальную документацию библиотеки в `library`. В `design/ui-library.md` опишите:

- семантические токены и соответствие вашим стилям;
- обязательные компоненты и их варианты/состояния;
- разрешённые размеры, плотность, типографику;
- когда допустим новый компонент;
- способ проверки и передачи макета разработчику.

Выбор библиотеки в правилах не требует изменения MCP. Новые возможности исполнения — например импорт библиотек, создание наборов вариантов или проверка разрешённых компонентов на уровне сервера — требуют доработки кода.

## Общие правила для всех получателей

Изменяйте исходный скилл в папке пакета и пересобирайте ZIP:

| Файл | Что менять |
| --- | --- |
| `skills/figma-local-design/SKILL.md` | Назначение, триггеры и основные ограничения |
| `references/design-workflow.md` внутри скилла | Порядок проектирования и проверки |
| `references/project-rules.md` | Правила чтения проектной конфигурации |
| `references/shadcn-ui.md` | Профиль UI-библиотеки |
| `assets/shadcn-starter.json` | Стартовые токены |
| `assets/design.config.example.json` | Пример проектных правил |

Пример запроса для доработки:

> Используй $figma-local-design. Добавь в скилл профиль нашей UI-библиотеки по design/ui-library.md, сохрани существующий shadcn-профиль и подготовь новый архив для команды.

Для изменения API:

> Используй $figma-local-design. Добавь в MCP создание ComponentSet с вариантами через Plugin API, без REST API. Обнови схемы, тесты и инструкции, пересобери пакет.
