# Изображения, варианты и прототипы

Эти инструменты появились в локальном MCP и плагине 0.7.0. Перед использованием проверьте наличие инструмента и `get_connection.document.pluginVersion`. Если инструменты отсутствуют после обновления, перезапустите MCP-клиент. Если плагин возвращает Unknown command, закройте и заново запустите его. Не подменяйте недостающий инструмент официальным MCP или произвольным JavaScript.

## Фотографии и SVG

- `import_image`: передайте абсолютный `filePath` существующего локального PNG/JPEG/GIF. Альтернатива — `dataBase64` без префикса data URL. Только один источник. Не выдумывайте пути; используйте предоставленные пользователем или подготовленные для его задачи файлы. Сервер сам читает байты, не отправляя локальный путь плагину и не загружая URL.
- Для нового изображения задайте `parentId`, `name`, координаты и нужные размеры. При одном размере второй вычисляется пропорционально; при двух размерах `scaleMode: FILL` заполняет область с обрезкой, `FIT` вписывает изображение. По умолчанию используется FILL.
- Для замены фотографии в существующей карточке передайте `nodeId`, источник и `scaleMode`, без родителя и геометрии. Команда заменяет весь список заливок узла; сначала прочитайте его. Координаты, размер и дочерние элементы сохраняются.
- Лимит файла — 8 MiB, размеры изображения — до 4096 px по каждой стороне. Сначала уменьшите слишком большое изображение подходящим инструментом. WebP и другие форматы предварительно преобразуйте в поддерживаемый формат. Не обещайте воспроизведение анимации GIF: инструмент использует image fill.
- `import_svg`: передайте `filePath` или строку `svg`, а также `parentId`, имя и координаты. `width` масштабирует всё дерево пропорционально. Результат — FRAME с редактируемыми векторами, а не растр.
- SVG должен состоять из статических фигур, путей, групп, локальных градиентов/масок. Поддерживаются только локальные ссылки `#id`. Скрипты, внешние ресурсы, CSS-блоки, встроенные картинки и текстовые SVG-элементы не поддерживаются. Для текста используйте TEXT-узлы или подготовленный SVG с контурами. Предел: 1 MiB, 5000 элементов, 64 уровня вложенности.

Проверяйте результат через `get_node` и экспорт родительского фрейма. Ограничение импорта — не гарантия совместимости всех эффектов SVG с Figma.

## Варианты компонентов

1. Найдите локальные COMPONENT-источники или создайте нужные состояния через `create_scene`. Обычные FRAME не являются компонентами.
2. Вызовите `create_component_set` с именем, родителем и `variants`: каждый элемент содержит `componentId` и `properties`, например `{"State":"Default","Size":"M"}`. Все варианты используют одинаковые имена свойств и разные комбинации значений. Предел — 2–50 вариантов и 1–8 свойств; запятые и знаки равенства в названиях/значениях не допускаются.
3. Команда создаёт **копии** источников. Исходные компоненты и их существующие экземпляры не переключаются на новый набор. Не удаляйте источники, чтобы «убрать дубликаты», без задачи на такую очистку.
4. Используйте возвращённый ID нужного варианта в `create_instance`. ID ComponentSet не подходит вместо COMPONENT.
5. Через `get_node` читайте `componentPropertyDefinitions`, `variantProperties` и `componentProperties`. Для существующего экземпляра используйте `set_instance_properties` с точными именами свойств. Поддерживаются VARIANT, BOOLEAN и TEXT; суффиксы вида `#...` у BOOLEAN/TEXT нужно сохранять. Создание новых определений свойств и INSTANCE_SWAP пока не реализовано.

Это реальные локальные варианты Figma. Они не являются импортом внешнего UI-кита. Выбор варианта меняет экземпляр; он сам по себе не создаёт интерактивную реакцию на hover/click.

## Прототипные переходы

- `set_prototype_link` связывает `nodeId` с действием. События: ON_CLICK, ON_HOVER, ON_PRESS. Действия: NAVIGATE, OVERLAY, CHANGE_TO, BACK, CLOSE.
- Для NAVIGATE и OVERLAY нужен `destinationId` верхнеуровневого FRAME на той же странице. NAVIGATE не должен вести на экран, содержащий источник: для пункта текущего экрана пропустите такую связь. Начиная с 0.7.3 серверный плагин отклоняет её до записи, сохраняя прежние реакции. Для BACK и CLOSE `destinationId` не передаётся.
- CHANGE_TO связывает разные варианты одного ComponentSet: источник — вариант или его дочерний узел, назначение — другой COMPONENT того же набора. Это позволяет сделать интерактивное состояние кнопки.
- `transition` может быть INSTANT, DISSOLVE или SMART_ANIMATE. `durationMs` задаётся в миллисекундах. BACK/CLOSE используют только INSTANT. Для SMART_ANIMATE согласуйте имена и структуру слоёв; запись перехода не гарантирует желаемую анимацию.
- Другие события узла сохраняются. Если реакция на выбранное событие уже есть, сначала изучите `reactions` через `get_node`; только затем используйте `replaceExisting: true`, если замена входит в задачу. Заменяются все реакции именно этого события, а не весь прототип.
- `set_prototype_start` задаёт имя потока и его `frameId`, сохраняя другие точки старта на странице. Одинаковые имена разных потоков отклоняются.

Проверьте сохранённые `reactions` и `flowStartingPoints`. Для проверки кликов и анимации откройте прототип в Figma Present. PNG подтверждает только статический вид; не сообщайте, что взаимодействие протестировано, если проверена лишь структура или мок API. Ошибки обновления свойств/реакций могут оставлять частичные изменения: прочитайте узел или используйте Undo перед повтором.
