# Ручная установка плагина в Figma

Используйте эту инструкцию после подготовки MCP установщиком скилла. Установка скилла из SkillStore и регистрация MCP подготавливают файлы на компьютере. Импорт плагина в Figma и его запуск — отдельный ручной шаг. Агент должен показать эти шаги пользователю, даже если Finder уже открыт.

## Что делает агент

1. Завершает запуск `scripts/install.mjs` и получает фактический путь `Figma manifest` из его результата. Если этот путь потерян, читает `installation.json.packageRoot` и проверяет наличие `generated/figma-plugin/manifest.json`, `code.js` и `ui.html` в этой установке.
2. Показывает абсолютный путь к папке плагина отдельным блоком, удобным для копирования. Не подставляет путь автора или старой резервной копии. При изменённом `CODEX_HOME` или `--target` использует фактический путь.
3. Даёт шаги ниже. Открытый Finder или успешный установщик ещё не подтверждают, что плагин импортирован и запущен.
4. После сообщения «готово» проверяет `get_connection`, затем `get_document` и бюджет страниц. Не создаёт пробные страницы. Если инструменты MCP ещё не появились, просит перезапустить MCP-клиент; это не повод повторять установку.

## Шаги для пользователя

1. Откройте **Figma Desktop** и нужный файл дизайна. Если MCP только что добавлен в Codex, перезапустите Codex.
2. В Figma выберите **Plugins → Development → Import plugin from manifest**. Нужен раздел Plugins, не Widgets.
3. В окне выбора файла перейдите в папку, которую показал агент:
   - **macOS:** нажмите **⌘⇧G** (Command + Shift + G), вставьте полный путь к папке и нажмите Enter. Это работает и для скрытой `.codex`. При необходимости скрытые файлы можно показать сочетанием **⌘⇧.** (Command + Shift + точка).
   - **Windows:** вставьте полный путь к папке в адресную строку окна выбора файла и нажмите Enter.
4. Выберите **manifest.json**. Оставьте его рядом с `code.js` и `ui.html`; перенос одного manifest в Downloads приводит к ошибке загрузки кода.
5. Запустите **Plugins → Development → Figma Local MCP Auto** в нужном файле. Одного импорта недостаточно: плагин должен быть запущен, его окно — открыто.
6. Дождитесь статуса **«Подключено. MCP может читать и редактировать этот файл.»** Код сопряжения вводить не нужно. Если написано **«Отключено»**, нажмите **«Подключить»**.
7. Напишите агенту «готово», чтобы он подтвердил связь с нужным файлом.

Типовой путь на macOS — `~/.codex/figma-local-mcp/generated/figma-plugin/`, но агент должен выдать реальный абсолютный путь конкретной установки.

## Если подключение не получилось

- **Видно поле для кода:** вероятно, запущена старая ручная версия. Закройте её и импортируйте manifest именно из `generated/figma-plugin/` текущей установки. Исходный `plugin/manifest.json` относится к ручному варианту.
- **`ENOENT ... code.js`:** выбран отдельный или перемещённый manifest. Импортируйте файл из полной папки нового плагина.
- **Ошибка `containsWidget`:** использован импорт виджета. Повторите через Plugins, не добавляйте `containsWidget` в manifest.
- **После чистой переустановки остался старый импорт:** уберите только записи этого плагина из Development и импортируйте новый manifest. Документы и макеты удалять не нужно.
- **После «Подключить» остаётся ошибка:** сообщите агенту полный текст статуса. Агент проверяет новый процесс MCP и порт 3055, актуальный manifest и совпадение локальной пары, не выводя ключ в чат. Не просит многократно переустанавливать всё без выяснения причины.

Не перемещайте папку установленного плагина после импорта: Figma читает его файлы по сохранённому пути.
